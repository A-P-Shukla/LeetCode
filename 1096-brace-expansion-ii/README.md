## Intuition
The expression follows a tiny grammar:

* A single letter → a set containing that letter.  
* `{e1,e2,…}` → union of the sets represented by the inner expressions.  
* Concatenation of two expressions → Cartesian product (all possible concatenations).

The natural way to evaluate such an expression is **recursive descent parsing**.  
We parse the string from left to right, building the set of strings generated by each sub‑expression.

* **parseConcat** – evaluates a sequence of terms that are *concatenated* (e.g. `a{b,c}d`). It repeatedly obtains the set for the next term and merges it with the current result by cartesian product.
* **parseSet** – evaluates a union inside braces `{ … }`. It calls `parseConcat` for each comma‑separated part, unions the results, and stops at the matching `}`.

Both functions return the computed set and the position of the next character to process.  
Using `std::unordered_set` guarantees uniqueness while we are building the result; a final sort produces the required ordered list.

## Complexity Analysis
Let **N** be the length of the input ( ≤ 60 ) and **K** the total number of distinct words generated.

*Time*: Each character is examined a constant number of times, and for every concatenation we perform a Cartesian product of two intermediate sets. The total work is proportional to the size of all intermediate sets, i.e. **O(K · L)** where **L** is the average word length (bounded by N).  

*Space*: We store at most **K** words in the unordered set plus recursion stack depth **O(N)**, yielding **O(K · L)** auxiliary space.
